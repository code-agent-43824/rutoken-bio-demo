# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Документация репозитория, интерфейс и сообщения в коде — на русском языке. Придерживайтесь этого.
Перед содержательными изменениями прочитайте `AGENTS.md`: там зафиксированы исходные требования
к демо и история принятых решений; его же обновляйте, когда меняете поведение.

## Команды

```bash
node test.js                  # вся проверка проекта (без зависимостей, без package.json)
python3 -m http.server 8000   # локальный запуск, затем http://localhost:8000
```

Сборки, линтера и менеджера пакетов нет. `test.js` — единственный набор проверок и запускается целиком;
отдельного «одного теста» не существует — чтобы сузить прогон, временно закомментируйте лишние
`assert`-блоки в конце IIFE.

Реальную работу с биометрией проверить в CI невозможно: нужен браузер с установленным плагином
Рутокен и подключённый токен Рутокен Био. `test.js` покрывает только логику на подменённом плагине.

## Архитектура

Статическая страница из четырёх файлов в корне: `index.html`, `style.css`, `script.js`, `test.js`.
GitHub Pages публикует корень ветки `main` как есть, поэтому любой файл в корне попадает в прод.
Плагин подключается внешним `<script>` с демо-портала Актив (`aktivco.github.io/rutoken-plugin-demo/rutoken-plugin.js`)
и даёт глобальный `window.rutoken`; собственных зависимостей нет.

`script.js` — один IIFE с `'use strict'`. Поток: `loadPlugin()` → `refreshDevices()` → `login()` →
`refreshKeys()` / `createKeyPair()` → `signData()`, плюс три кнопки биометрии (`loginBio`, `logoutBio`,
`stopLoginBio`) и журнал.

### Ограничения, которые задаёт `test.js`

`test.js` не использует jsdom: он собирает свой `global.document`, `global.window` и фальшивый `plugin`,
затем делает `require('./script.js')`. Поэтому в `script.js` можно опираться только на то, что умеет
подменённый DOM:

- доступ к элементам — исключительно `document.getElementById` и `document.createElement`
  (никаких `querySelector`, `dataset`, `remove()`);
- `innerHTML` можно только присваивать пустую строку — `FakeElement` падает на любом другом значении;
- таймеры и буфер обмена — через `window.setTimeout` / `window.clearTimeout` / `window.navigator.clipboard`,
  не через глобальные функции;
- каждый обработчик события регистрируется один раз на элемент: `addEventListener` в фейке перезаписывает
  предыдущий обработчик того же типа.

Новый элемент с `id` нужно одновременно добавить в `index.html` и в массив `ids` в `test.js`, иначе
`getElementById` вернёт `undefined` и тест упадёт на старте.

Тесты сверяют и разметку (`value="12345678"` у `#pinInput`, ровно пять `.step-number`), и точные тексты
сообщений (`'Плагин загружен ✓'` и др.), и иконки ключей (`🔬` / `🔑` / `❔`). Меняя формулировки,
правьте `test.js` в том же коммите.

### Инварианты поведения

**Кэш GitHub Pages.** `BUILD_ID` в `script.js` и `?v=` в теге `<script src="script.js?v=...">` внутри
`index.html` должны совпадать. Любое изменение `script.js` сопровождается подъёмом обеих строк, иначе
у пользователей останется старая версия.

**Журнал не содержит секретов.** `log()` — сообщения для пользователя, `debug()` — трассировка
(скрыта, пока на `#consoleSection` нет класса `detailed`). Всё, что уходит в `debug`, проходит через
`safeJson()`, который маскирует ключи `pin|password|payload|data` и обрезает длинные строки. PIN и
подписываемые данные не должны попадать в журнал ни в каком виде — это проверяется тестом на
скопированном содержимом консоли. Передавайте в `trace()` длину (`pinLength`, `dataLength`), а не значение.

**Порядок операций с био-ключом.** Любая защищённая операция идёт по цепочке
`isLoginBioRequired → loginBio(deviceId, {objectId: keyId, timeout}) → операция → logoutBio`.
Эта последовательность реализована в `authorizeBioObject()` (метка, удаление) и повторена явно
в `signData()`; новые операции над био-ключами подключайте к `authorizeBioObject()`, а не пишите заново.
`performBioLogin()` оборачивает callback-стиль `plugin.loginBio` в промис и защищает от повторного вызова callback.

**Предварительная проверка перед созданием био-ключа.** `preflightBioKey()` читает `TOKEN_INFO_BIO_ATTEMPTS_INFO`;
нулевые счётчики блокируют генерацию, а неопределённые (`null`/нечисловые) — не блокируют, а
подтверждаются реальным `loginBio` в `confirmBioReady()`. Это поведение зафиксировано тестом:
недоступные счётчики не должны ломать сценарий.

**Состояние биометрии** живёт в трёх переменных модуля: `bioSessionActive` (открыта ли био-сессия),
`bioReadyConfirmed` (готовность подтверждена отпечатком) и `knownKeyProtection` (тип защиты ключа,
запомненный на время сессии, — нужен потому, что `isLoginBioRequired` возвращает `false`, пока открыта
био-сессия). Смена устройства сбрасывает первые два.

**Защита от гонок.** `deviceRefreshGeneration` и `keyRefreshGeneration` инкрементируются в начале
каждого обновления; результат применяется к DOM, только если поколение всё ещё актуально. Любой новый
асинхронный рендер списков должен делать такую же проверку.

**Список ключей обновляется только вручную.** Ни успешный вход по PIN, ни создание ключа не вызывают
`refreshKeys()` — вместо этого показывается подсказка через `showKeyListHint()`. Это намеренно
(чтение ключей — дорогая операция на токене) и закреплено тестами.

**Коды ошибок плагина** распознаются по префиксу в тексте сообщения через `hasErrorCode(error, 19)`:
19 — требуется вход, 93 — вход уже выполнен.

### Стиль кода

`script.js` написан в ES5-совместимой манере: `function` вместо стрелок, явные промис-цепочки вместо
`async/await`, `var`-подобное использование `const`/`let` на уровне модуля. Новый код пишите так же.
Внешние вызовы плагина оборачивайте в `trace(operation, details, action, summarizeResult)` — это даёт
единообразные записи `*.start` / `*.success` / `*.error` с временем выполнения.

Цвета и отступы в `style.css` заданы CSS Custom Properties в `:root` (`--rt-red`, `--rt-teal`, …);
новые оттенки добавляйте туда, а не в правила.
