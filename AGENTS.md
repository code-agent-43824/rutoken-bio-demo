## Правила кодинга (веб)

Применяются для проектов на HTML/CSS/JavaScript (веб-фронтенд).

### Кодинг

- Стандарты: HTML5, CSS3, ES6+ (vanilla JS, без фреймворков, если не указано иное).
- Отступы: **2 пробела**, без табов.
- Имена классов CSS: `kebab-case`.
- Имена функций и переменных JS: `camelCase`.
- Имена констант JS: `UPPER_SNAKE_CASE`.
- DOM-элементы получать через `document.getElementById` (id — `camelCase`).
- Весь JS — в IIFE (изоляция scope) в режиме `'use strict'`.
- Без внешних зависимостей, если не требуется иначе.

### Структура

```
├── index.html      # Единственная страница (одностраничник)
├── style.css       # Стили
├── script.js       # Логика (IIFE)
└── README.md
```

### Сборка и запуск

- Проект — статический сайт, сборка не требуется.
- Локальный запуск: `python3 -m http.server 8000` → http://localhost:8000
- Для работы плагина Рутокен требуется браузер с расширением
  «Адаптер Рутокен Plugin» и подключённый токен.

### Git / коммиты

- Пушить напрямую в `main`, без feature-веток и MR.
- Коммиты — на английском, в императиве (`Add calculator UI`).
- Секреты (токены, ключи) никогда не коммитить.

### CI/CD

- Пайплайн: `pages` (GitLab Pages — копия фронтенда) → `release` (тар-архив
  → Package Registry → GitLab Release при пуше тега).
- Релиз — только пушем тега `vX.Y.Z` (SemVer).
- Артефакты — в Package Registry GitLab, ссылка на релиз — пользователю.
